# 026 — Set

A **Set** is a data type that stores **unique** items: if a value appears more than once, the Set keeps one copy. Think of it as a group of items, not a row with a fixed order.

> [!MENTAL-MODEL]
> **Set = unique, unordered values with no index.** Use it when membership and removing duplicates matter more than position.

## Creating a Set

Create a Set with braces `{}` and separate items with commas:

```python
my_set = {"Ahmed", "Mohamed", "Ali"}

print(my_set)
```

```example-output
{'Mohamed', 'Ali', 'Ahmed'}
```

This is **example output** because Python does not guarantee the display order of Set items. The names may appear in a different order, but the content remains `Ahmed`, `Mohamed`, and `Ali`.

> [!IMPORTANT]
> `{}` by itself creates an empty Dictionary, not an empty Set. Use `set()` to create an empty Set.

## Sets are unordered and do not support indexing

Lists and Tuples have indexes because their items are stored as an ordered sequence. A Set is different: there is no item that is always “item zero.”

```python
my_set = {"Ahmed", "Mohamed", "Ali"}

print(my_set[0])
```

```error
TypeError: 'set' object is not subscriptable
```

The error occurs because `my_set[0]` tries to index a type that does not support indexing. For the same reason, slicing such as `my_set[1:3]` is unavailable.

## Items are unique and duplicates disappear

```python
numbers = {1, 2, 3, 1, 2, 3}

print(numbers)
```

```example-output
{1, 2, 3}
```

Each of `1`, `2`, and `3` is written twice, but the Set stores each value once. Display order may vary, while the number of unique values stays fixed at `3`.

This is useful when you have repeated names or IDs and only need the distinct values.

## Items must be immutable

An item inside a Set must be **hashable**. At an introductory level, that means its value must not change while it is used as a Set item. Numbers, Strings, and Tuples containing fixed values are suitable:

```python
data = {
    10,
    "Python",
    (1, 2, 3)
}

print(data)
```

```example-output
{10, 'Python', (1, 2, 3)}
```

The Tuple is accepted because it is immutable. A List such as `[1, 2, 3]` cannot be a Set item because it is mutable.

```python
data = {10, [1, 2, 3]}
```

```error
TypeError: unhashable type: 'list'
```

> [!COMPARISON]
> **List:** ordered, supports indexes and slices, allows duplicates, and is mutable.
> **Tuple:** ordered, supports indexes and slices, allows duplicates, and is immutable.
> **Set:** unordered, does not support indexes or slices, and removes duplicates.

## Quick mental model

- Need order and item positions? Use a sequence such as a List or Tuple.
- Need unique values and membership checks? A Set is a natural choice.
- Do not rely on the order in which a Set prints.
- Do not put a List or Dictionary directly inside a Set.
