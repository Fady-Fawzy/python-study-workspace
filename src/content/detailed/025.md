# 025 — Tuples And Methods Part 2

Now that we know Tuples are ordered and immutable, we can cover the practical details: one-item Tuples, concatenating and repeating sequences, `count()` and `index()`, and assigning Tuple values to variables through **unpacking**.

## One-item Tuples: the comma is the key

Parentheses alone do not create a **single-item Tuple**. `("Python")` is simply a String inside grouping parentheses, while `("Python",)` is a Tuple because it contains a comma.

```python
not_a_tuple = ("Python")
tuple_one = ("Python",)
tuple_two = "Python",

print(type(not_a_tuple))
print(tuple_one)
print(tuple_two)
print(type(tuple_one))
print(type(tuple_two))
print(len(tuple_one))
```

```output
<class 'str'>
('Python',)
('Python',)
<class 'tuple'>
<class 'tuple'>
1
```

`not_a_tuple` has type `str` because parentheses did not change the value's type. In `tuple_one` and `tuple_two`, the comma tells Python that the structure is a Tuple, and `len(tuple_one)` confirms that it contains one item.

> [!WARNING]
> Forgetting the comma is the most common mistake: `("Python")` is not a one-item Tuple. Write `("Python",)`, or `"Python",` when the context is clear.

> [!MENTAL-MODEL]
> For a one-item Tuple, parentheses provide clarity; **the comma creates the type**.

## Concatenation: joining Tuples

The `+` operator joins one Tuple to another and creates a new Tuple containing the items in order.

```python
a = (1, 2, 3)
b = (4, 5)

c = a + b

print(c)
```

```output
(1, 2, 3, 4, 5)
```

Python takes the items from `a` first and then the items from `b`. It does not change either original; it creates a new object and assigns it to `c`, which fits Tuple immutability.

> [!IMPORTANT]
> Immutability does not prevent creating a new Tuple from old Tuples. It prevents changing slots inside an existing Tuple.

## Repeat: repeating a sequence with `*`

The `*` operator repeats a String, List, or Tuple the requested number of times.

```python
my_string = "Python "
my_list = [1, 2]
my_tuple = ("A", "B")

print(my_string * 3)
print(my_list * 3)
print(my_tuple * 3)
```

```output
Python Python Python
[1, 2, 1, 2, 1, 2]
('A', 'B', 'A', 'B', 'A', 'B')
```

The String repeats three times; the space inside `"Python "` separates the words and leaves a final space before the print newline. The List and Tuple items repeat in their original order for three cycles.

> [!COMPARISON]
> `sequence * 3` has the same idea for all three types: repeat the content. The result keeps the sequence type: a String produces a String, a List produces a List, and a Tuple produces a Tuple.

## `count()` — number of occurrences

Tuple `count(value)` returns the number of matching values, using the same idea as List `count()`.

```python
numbers = (1, 3, 7, 8, 2, 8, 8)

print(numbers.count(8))
```

```output
3
```

The number `8` appears three times, so the returned value is `3`. The Tuple itself is unchanged.

## `index()` — position of the first match

`index(value)` returns the index of the first matching value, and counting starts at zero.

```python
numbers = (10, 20, 30, 40)

print(numbers.index(30))
```

```output
2
```

`30` is the third item when displayed, but Python's positions are `0`, `1`, `2`, `3`, so its index is `2`.

> [!IMPORTANT]
> Like `list.index()`, `tuple.index()` raises `ValueError` when the value is missing.

## Tuple unpacking: assign values to variables

**Unpacking**, also called destructuring, assigns Tuple items to separate variables in one line.

```python
person = ("Ahmed", 25, "Egypt")

name, age, country = person

print(name)
print(age)
print(country)
```

```output
Ahmed
25
Egypt
```

The assignment follows order:

| Variable | Received value |
| --- | --- |
| `name` | `"Ahmed"` |
| `age` | `25` |
| `country` | `"Egypt"` |

Each variable receives the value at the corresponding position. In ordinary unpacking, the number of variables must match the number of values.

```python
name, age = person
```

```error
ValueError: too many values to unpack (expected 2)
```

The Tuple has three values, but the left side provides only two variables, so Python has nowhere to put the third value.

## Ignoring a value with `_`

When we receive a value that we do not need here, the conventional variable name is `_`.

```python
person = ("Ahmed", 25, "Egypt")

name, _, country = person

print(name)
print(country)
```

```output
Ahmed
Egypt
```

The value `25` really is assigned to `_`, but the name tells the reader: “I received this value, but I do not need it here.”

> [!IMPORTANT]
> `_` is a convention, not a reserved word. Technically it is a **valid variable name** and can be read, but it is best to respect the convention and not rely on its value when you mean to ignore it.

## Final mental model

| Idea | Meaning |
| --- | --- |
| `("Python",)` | One-item Tuple; the comma is required |
| `a + b` | A new concatenated Tuple |
| `data * 3` | Repeat a sequence |
| `count(value)` | Number of occurrences |
| `index(value)` | Position of the first occurrence |
| `a, b, c = tuple_data` | Unpack in order |
| `_` | A valid variable conventionally used for an unneeded value |

> [!COMPARISON]
> Lists and Tuples both support order, indexing, `count()`, and `index()`. Operations such as `+` and `*` create new Tuples; item assignment is not available because Tuples are immutable.
