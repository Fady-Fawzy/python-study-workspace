# 031 — Dictionary Methods Part 1

Dictionaries are mutable: we can clear them, add or update pairs, and copy them. This lesson explains the difference between operations that change the same Dictionary and operations that create a copy.

## `clear()` — empty a Dictionary

```python
user = {
    "name": "Ahmed",
    "age": 25
}

test = user.copy()
test.clear()
print(test)
```

```output
{}
```

`test.clear()` removes every `key: value` pair from `test` itself. Because we used a copy, the original `user` still contains `name` and `age`.

> [!IMPORTANT]
> `clear()` changes the same object and returns `None`. Do not write `empty = test.clear()` expecting an empty Dictionary; `empty` will contain `None`.

## `update()` — add or update pairs

```python
user.update({"country": "Egypt"})
print(user)
```

```output
{'name': 'Ahmed', 'age': 25, 'country': 'Egypt'}
```

The key `country` was missing, so `update()` adds it. If you pass an existing key, its value is updated instead of creating a duplicate key.

If you use `update()` with the existing `age` key, its value is replaced instead of creating a second key because every key must remain unique.

## Direct assignment through a key

```python
user["skill"] = "Python"
print(user)
```

```output
{'name': 'Ahmed', 'age': 25, 'country': 'Egypt', 'skill': 'Python'}
```

The assignment `user["skill"] = "Python"` adds the pair when the key is new and replaces the value when the key already exists.

> [!COMPARISON]
> `user[key] = value` is clear for adding or updating one pair.
> `user.update({...})` is useful for adding or updating several pairs together.

## `copy()` — copy the outer level

```python
copied_user = user.copy()
print(copied_user)
```

```output
{'name': 'Ahmed', 'age': 25, 'country': 'Egypt', 'skill': 'Python'}
```

At copy time, `copied_user` has the same pairs but is a different Dictionary object. Adding a new key to one does not automatically add it to the other.

The copy is **shallow**: the outer Dictionaries are separate. If values are nested mutable objects, their inner sharing needs a deeper study later.

## `keys()` — a view of keys

```python
print(user.keys())
```

```output
dict_keys(['name', 'age', 'country', 'skill'])
```

`keys()` does not return values; it returns the keys used to access data. The result is a view connected to the Dictionary, not an independent List.

## `values()` — a view of values

```python
print(user.values())
```

```output
dict_values(['Ahmed', 25, 'Egypt', 'Python'])
```

Each value corresponds to its key in the same insertion order: `name → Ahmed`, then `age → 25`, and so on.

## Running the complete example

When you run the source example in order, `test.clear()` does not change `user`, then `country` and `skill` are added, and finally the copy is created. This shows why tracking the variable before the dot matters: each method runs on a specific object.

> [!WARNING]
> Do not confuse `test.clear()` with `user.clear()`. The method changes only the Dictionary written before the dot.

## Quick mental model

- `clear()` = remove every pair from the same Dictionary.
- `update()` = add or update pairs.
- `dictionary[key] = value` = direct work with one pair.
- `copy()` = a separate outer copy.
- `keys()` and `values()` = views of each side of the pairs.
